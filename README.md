# Zaslon

Kill switch для отдельных приложений на macOS. Живёт в меню-баре.

Если VPN отключился, публичный IP сменился или пропал интернет, Zaslon ставит выбранные приложения на паузу (`SIGSTOP`). Если разрешённый IP вернулся за отведённое время (`grace`, по умолчанию 20 с), приложения продолжают работу с того же места (`SIGCONT`). Если не вернулся, Zaslon закрывает их: сначала просит завершиться (`SIGTERM`), затем закрывает принудительно (`SIGKILL`). Пока IP не разрешён, новые запуски этих приложений сразу завершаются.

- Белый список: адреса, подсети и страны.
- IP сверяется по пяти независимым сервисам. Отдельно проверяются утечка IPv6 и DNS-резолвер.
- Реагирует на смену сети сразу, не дожидаясь очередной проверки.
- В меню-баре видны статус, страна и IP. Есть окно настроек и окно выбора приложений.
- Лог всех пауз с причинами.
- Без прав администратора, без облака, без телеметрии.

## Требования

macOS 13 или новее, Apple Silicon или Intel.

## Установка

1. Скачай `Zaslon-<версия>.dmg` со страницы [Releases](../../releases).
2. Открой образ и перетащи Zaslon в «Программы».
3. Запусти Zaslon. Сборка подписана ad-hoc, без Developer ID, поэтому при первом запуске macOS его заблокирует. Чтобы разрешить:
   - macOS 15 и новее: «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»;
   - macOS 13–14: правый клик по приложению → «Открыть»;
   - или в Терминале: `xattr -dr com.apple.quarantine /Applications/Zaslon.app`.

## Первый запуск

При первом запуске текущий IP попадает в белый список, поэтому запускай Zaslon с включённым VPN. По умолчанию защищён Claude (`/Claude.app/`), остальные приложения выбираются в настройках.

Автозапуск включается в настройках (раздел «Запуск») или пунктом меню «Запускать при входе в систему». Zaslon добавляется в «Объекты входа» по тому пути, откуда он запущен, поэтому включай автозапуск в копии из «Программ».

## Настройки

Окно «Настройки…» открывается из меню (⌘,):

- защищённые приложения: кнопка «Выбрать приложения…» открывает список установленных и запущенных программ с поиском; для CLI-инструментов есть поле «своё правило»;
- разрешённые IP, подсети и страны;
- автозапуск;
- таймеры, число согласных IP-сервисов и проверка IPv6, у каждого параметра есть пояснение.

Изменения применяются сразу. Если приложение убрать из защиты, пока оно на паузе, оно тут же продолжает работу.

Настройки хранятся в `~/Library/Application Support/Zaslon/config.json`. Файл можно править и руками: Zaslon перечитывает его при сохранении.

| ключ | по умолчанию | смысл |
|---|---|---|
| `apps` | `["/Claude.app/"]` | подстроки командной строки процесса (`ps -o command`), без учёта регистра |
| `allow_ips` | текущий IP | адреса и подсети: `"185.12.40.0/24"`, `"2001:db8::/32"` |
| `allow_countries` | `[]` | коды стран: `["NL", "DE"]` |
| `grace` | `20` | сколько секунд держать паузу до закрытия |
| `close_timeout` | `5` | сколько секунд дать приложению на сохранение между `SIGTERM` и `SIGKILL` |
| `check_interval` | `5` | сколько секунд между проверками, когда всё в порядке |
| `min_agree` | `2` | сколько IPv4-сервисов должны назвать один адрес |
| `check_ipv6` | `true` | считать ли утечкой IPv6-адрес не из белого списка |

## Лог

Лог пишется в `~/Library/Logs/Zaslon.log`. Открыть его можно пунктом меню «Открыть лог» (⌘L): он откроется в «Консоли». В лог попадают:

- старт и выход;
- события сети с интерфейсами;
- каждая пауза с причиной;
- каждое возобновление с длительностью;
- закрытие приложений;
- неудачные проверки с ответами сервисов;
- изменения настроек;
- автозапуск;
- сон и пробуждение.

Когда файл вырастает больше 1 МБ, он переименовывается в `Zaslon.log.1`.

## Как устроено

- IPv4 запрашивается у пяти сервисов параллельно. Адрес принимается, когда `min_agree` из них назвали один и тот же. Если из-за медленной сети ответили не все, но все ответившие назвали один адрес, он тоже принимается. Пауза наступает в трёх случаях: сервисы называют разные адреса, не отвечает ни один, адрес не из белого списка.
- IPv6 запрашивается у трёх сервисов, достаточно одного ответа.
- Страна определяется через `ipinfo.io`, при неудаче через `api.country.is`. Ответ кэшируется.
- Если сеть пропала или изменился набор интерфейсов (например, исчез туннель VPN `utun`), приложения ставятся на паузу сразу, и IP перепроверяется. Если IP прежний, через 1–2 с они продолжают работу. На остальные события сети (DNS, роуминг Wi-Fi) IP перепроверяется без паузы.
- Во время паузы проверка идёт каждые 2 с, в нормальном режиме раз в `check_interval`.
- Время, пока Mac спал, не входит в паузу до закрытия: после пробуждения отсчёт `grace` начинается заново.
- При выходе из Zaslon и при его остановке сигналом все приложения продолжают работу. При старте Zaslon снимает паузу со всех подходящих процессов на случай, если прошлый запуск завершился аварийно.

## Что уходит в сеть

Только запросы для проверки адреса:

- IPv4: `api.ipify.org`, `ipv4.icanhazip.com`, `v4.ident.me`, `checkip.amazonaws.com`, `ipinfo.io/ip`;
- IPv6: `api6.ipify.org`, `ipv6.icanhazip.com`, `v6.ident.me`;
- страна по IP: `ipinfo.io`, `api.country.is`;
- DNS-запрос `whoami.akamai.net`, чтобы узнать адрес DNS-резолвера.

Больше Zaslon никуда не обращается и ничего не отправляет.

## Ограничения

- Защита работает на уровне приложений: сетевой трафик Zaslon не блокирует, и между сменой сети и паузой проходят доли секунды. Если важно, чтобы наружу не ушёл ни один пакет, включи ещё и kill switch в самом VPN-клиенте.
- Процессы root и других пользователей не затрагиваются.
- Проверяется общий публичный IP. Если VPN пускает часть доменов в обход туннеля (раздельная маршрутизация), Zaslon этого не видит.
- Вредоносная программа на том же Mac может просто завершить Zaslon.

## Сборка из исходников

Нужен Xcode. Зависимостей нет.

```sh
./build.sh                                        # build/Zaslon.app, универсальный бинарник
./dmg.sh                                          # build/Zaslon-<версия>.dmg
build/Zaslon.app/Contents/MacOS/Zaslon --check    # проверка IP без паузы и без записи конфига
open build/Zaslon.app
```

Две запущенные копии (из `build/` и из «Программ») работают независимо друг от друга, и каждая ставит приложения на паузу. Перед запуском одной закрой другую.

Иконку рисует `icon.swift` из векторов, каждый размер отдельно. Готовый `AppIcon.icns` лежит в репозитории. Пересобрать после правки:

```sh
xcrun --sdk macosx swiftc -sdk "$(xcrun --show-sdk-path)" icon.swift -o build/make-icon && build/make-icon AppIcon.icns
```

## Выпуск версии

1. Подними `CFBundleShortVersionString` в `Info.plist`.
2. Добавь раздел `## <версия> — ДД.ММ.ГГГГ` в `CHANGELOG.md`.
3. Создай и отправь тег: `git tag v<версия> && git push origin v<версия>`.

GitHub Actions (`.github/workflows/release.yml`) соберёт DMG и опубликует релиз. Описание релиза берётся из раздела CHANGELOG. Если тег не совпадает с версией в `Info.plist`, сборка остановится.
