# Zaslon

Kill switch для отдельных приложений на macOS и Windows. На macOS живёт в меню-баре, на Windows в области уведомлений. Ниже описана версия для macOS, отличия Windows-версии — в разделе [Windows](#windows).

Если VPN отключился, публичный IP сменился или пропал интернет, Zaslon ставит выбранные приложения на паузу (`SIGSTOP`). Если разрешённый IP вернулся за отведённое время (`grace`, по умолчанию 20 с), приложения продолжают работу с того же места (`SIGCONT`). Если не вернулся, Zaslon закрывает их: сначала просит завершиться (`SIGTERM`), затем закрывает принудительно (`SIGKILL`). Пока IP не разрешён, новые запуски этих приложений сразу завершаются.

- Белый список: адреса, подсети и страны.
- IP сверяется по пяти независимым сервисам. Отдельно проверяются утечка IPv6 и DNS-резолвер.
- Реагирует на смену сети сразу, не дожидаясь очередной проверки.
- В меню-баре видны статус, страна и IP. Есть окно настроек и окно выбора приложений.
- Лог всех пауз с причинами.
- Без прав администратора, без облака, без телеметрии.

## Требования

macOS 13 или новее, Apple Silicon или Intel.

## Установка

1. Скачай `Zaslon-<версия>.dmg` со страницы [Releases](../../releases).
2. Открой образ и перетащи Zaslon в «Программы».
3. Запусти Zaslon. Сборка подписана ad-hoc, без Developer ID, поэтому при первом запуске macOS его заблокирует. Чтобы разрешить:
   - macOS 15 и новее: «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»;
   - macOS 13–14: правый клик по приложению → «Открыть»;
   - или в Терминале: `xattr -dr com.apple.quarantine /Applications/Zaslon.app`.

## Первый запуск

При первом запуске текущий IP попадает в белый список, поэтому запускай Zaslon с включённым VPN. По умолчанию защищён Claude (`/Claude.app/`), остальные приложения выбираются в настройках.

Автозапуск включается в настройках (раздел «Запуск») или пунктом меню «Запускать при входе в систему». Zaslon добавляется в «Объекты входа» по тому пути, откуда он запущен, поэтому включай автозапуск в копии из «Программ».

## Настройки

Окно «Настройки…» открывается из меню (⌘,):

- защищённые приложения: кнопка «Выбрать приложения…» открывает список установленных и запущенных программ с поиском; для CLI-инструментов есть поле «своё правило»;
- разрешённые IP, подсети и страны;
- автозапуск;
- компактный режим строки меню: только цветная точка, без IP и страны;
- таймеры, число согласных IP-сервисов и проверка IPv6, у каждого параметра есть пояснение.

Изменения применяются сразу. Если приложение убрать из защиты, пока оно на паузе, оно тут же продолжает работу.

Настройки хранятся в `~/Library/Application Support/Zaslon/config.json`. Файл можно править и руками: Zaslon перечитывает его при сохранении.

| ключ | по умолчанию | смысл |
|---|---|---|
| `apps` | `["/Claude.app/"]` | подстроки командной строки процесса (`ps -o command`), без учёта регистра |
| `allow_ips` | текущий IP | адреса и подсети: `"185.12.40.0/24"`, `"2001:db8::/32"` |
| `allow_countries` | `[]` | коды стран: `["NL", "DE"]` |
| `grace` | `20` | сколько секунд держать паузу до закрытия |
| `close_timeout` | `5` | сколько секунд дать приложению на сохранение между `SIGTERM` и `SIGKILL` |
| `check_interval` | `5` | сколько секунд между проверками, когда всё в порядке |
| `min_agree` | `2` | сколько IPv4-сервисов должны назвать один адрес |
| `check_ipv6` | `true` | считать ли утечкой IPv6-адрес не из белого списка |
| `compact_menu_bar` | `false` | показывать в строке меню только цветную точку |

## Лог

Лог пишется в `~/Library/Logs/Zaslon.log`. Открыть его можно пунктом меню «Открыть лог» (⌘L): он откроется в «Консоли». В лог попадают:

- старт и выход;
- события сети с интерфейсами;
- каждая пауза с причиной;
- каждое возобновление с длительностью;
- закрытие приложений;
- неудачные проверки с ответами сервисов;
- изменения настроек;
- автозапуск;
- сон и пробуждение.

Когда файл вырастает больше 1 МБ, он переименовывается в `Zaslon.log.1`.

## Как устроено

- IPv4 запрашивается у пяти сервисов параллельно. Адрес принимается, когда `min_agree` из них назвали один и тот же. Если из-за медленной сети ответили не все, но все ответившие назвали один адрес, он тоже принимается. Пауза наступает в трёх случаях: сервисы называют разные адреса, адрес не из белого списка, не отвечает ни один две проверки подряд. Одна проверка без ответов паузу не вызывает: трафик в этот момент никуда не уходит, а повторная проверка запускается сразу.
- IPv6 запрашивается у трёх сервисов, достаточно одного ответа.
- Страна определяется через `ipinfo.io`, при неудаче через `api.country.is`. Ответ кэшируется.
- Если сеть пропала или изменился набор интерфейсов (например, исчез туннель VPN `utun`), приложения ставятся на паузу сразу, и IP перепроверяется. Если IP прежний, через 1–2 с они продолжают работу. На остальные события сети (DNS, роуминг Wi-Fi) IP перепроверяется без паузы.
- Во время паузы проверка идёт каждые 2 с, в нормальном режиме раз в `check_interval`.
- Время, пока Mac спал, не входит в паузу до закрытия: после пробуждения отсчёт `grace` начинается заново.
- При выходе из Zaslon и при его остановке сигналом все приложения продолжают работу. При старте Zaslon снимает паузу со всех подходящих процессов на случай, если прошлый запуск завершился аварийно.

## Что уходит в сеть

Только запросы для проверки адреса:

- IPv4: `api.ipify.org`, `ipv4.icanhazip.com`, `v4.ident.me`, `checkip.amazonaws.com`, `ipinfo.io/ip`;
- IPv6: `api6.ipify.org`, `ipv6.icanhazip.com`, `v6.ident.me`;
- страна по IP: `ipinfo.io`, `api.country.is`;
- DNS-запрос `whoami.akamai.net`, чтобы узнать адрес DNS-резолвера.

Больше Zaslon никуда не обращается и ничего не отправляет.

## Ограничения

- Защита работает на уровне приложений: сетевой трафик Zaslon не блокирует, и между сменой сети и паузой проходят доли секунды. Если важно, чтобы наружу не ушёл ни один пакет, включи ещё и kill switch в самом VPN-клиенте.
- Процессы root и других пользователей не затрагиваются.
- Проверяется общий публичный IP. Если VPN пускает часть доменов в обход туннеля (раздельная маршрутизация), Zaslon этого не видит.
- Вредоносная программа на том же Mac может просто завершить Zaslon.

## Windows

Версия для Windows лежит в `windows/` (C#, .NET 10, WinForms). Правила проверки IP те же: пять сервисов, `min_agree`, IPv6, белый список адресов, подсетей и стран, реакция на смену сети. Отличается способ защиты.

Если IP не разрешён, Zaslon не замораживает приложения, а блокирует им сеть правилом брандмауэра Windows: по правилу на входящие и исходящие соединения для каждого защищённого exe. Правила брандмауэра не действуют на loopback, поэтому на время блокировки Zaslon ставит ещё и фильтр WFP на исходящие соединения exe, включая соединения на `127.*`. Так блокируется и трафик, который приложение отправляет через локальный прокси VPN-клиента. Приложения продолжают работать, но наружу ничего не уходит. Установленные IPv4-соединения этих процессов, в том числе на `127.*`, Zaslon рвёт сразу. Когда разрешённый IP возвращается, правила и фильтры снимаются. Закрывать приложения незачем, поэтому `grace` и `close_timeout` в Windows-версии нет.

### Требования и установка

Windows 10 или 11, x64. Нужны права администратора: без них правила брандмауэра не меняются. Брандмауэр Windows должен быть включён. Если он выключен в активном профиле сети, Zaslon пишет предупреждение в меню и в лог.

1. Скачай `Zaslon-<версия>-win-x64.exe` со страницы [Releases](../../releases) и положи в постоянное место, например `C:\Program Files\Zaslon\`.
2. Запусти. Windows спросит разрешение UAC. Exe не подписан, поэтому SmartScreen может предупредить: «Подробнее» → «Выполнить в любом случае».
3. При первом запуске текущий IP попадает в белый список, поэтому запускай Zaslon с включённым VPN.

Автозапуск включается в настройках или пунктом меню значка. Zaslon создаёт задачу планировщика `Zaslon`: запуск при входе пользователя, с наивысшими правами, без запроса UAC, без лимита времени. В задачу записывается путь, откуда Zaslon запущен.

### Настройки

Меню открывается правым кликом по значку, окно настроек — двойным кликом. Цвет точки на значке: зелёный — защита активна, красный — сеть приложений заблокирована, серый — проверка или пауза.

Настройки хранятся в `%APPDATA%\Zaslon\config.json`, лог — в `%LOCALAPPDATA%\Zaslon\Zaslon.log`.

| ключ | по умолчанию | смысл |
|---|---|---|
| `apps` | `["\\claude.exe"]` | подстроки полного пути к exe, без учёта регистра |
| `allow_ips` | текущий IP | адреса и подсети |
| `allow_countries` | `[]` | коды стран |
| `check_interval` | `5` | сколько секунд между проверками, когда всё в порядке |
| `min_agree` | `2` | сколько IPv4-сервисов должны назвать один адрес |
| `check_ipv6` | `true` | считать ли утечкой IPv6-адрес не из белого списка |

Окно «Выбрать приложения…» собирает программы из меню «Пуск» и запущенные программы с окном. Правило для них — имя exe, например `\telegram.exe`.

### Как устроено

- Правила брандмауэра собраны в группу `Zaslon`. Пока сеть заблокирована, Zaslon раз в секунду ищет новые процессы защищённых exe и добавляет правила для их путей. Правило получают и exe, замеченные раньше за время работы, даже если сейчас они не запущены.
- Фильтры WFP живут в динамической сессии Zaslon и исчезают при его выходе или падении. Правила брандмауэра постоянные.
- Если Windows выключили или Zaslon упал во время блокировки, правила брандмауэра остаются. При следующем запуске Zaslon ставит для них фильтры WFP заново, и всё это действует до первой проверки: разрешённый IP — снимается, нет — остаётся.
- При выходе через меню все правила снимаются. Пауза защиты тоже снимает правила.
- Смена сети: появление или пропажа адаптера (например, адаптера VPN) или пропажа сети блокирует сразу. На прочие события IP перепроверяется без блокировки.
- Запущена может быть только одна копия Zaslon.

Снять правила вручную, если Zaslon удалён во время блокировки (PowerShell от администратора):

```powershell
Remove-NetFirewallRule -Group Zaslon
```

### Ограничения

- Правило брандмауэра действует на exe целиком. Если правило защиты совпадает с общим exe (`node.exe`, `python.exe`, `msedgewebview2.exe`), сеть теряют все программы, которые его используют. Приложения на WebView2 ходят в сеть через `msedgewebview2.exe`.
- Установленные IPv6-соединения и UDP-потоки (например, QUIC) Windows не позволяет разорвать извне. Новые соединения блокируются правилом.
- Сторонний брандмауэр, который отключает брандмауэр Windows, отключает и защиту.
- DNS-запросы приложений идут через системную службу DNS-клиента, их правило не блокирует.

### Проверка без блокировки

Из PowerShell, запущенного от администратора:

```powershell
.\Zaslon.exe --check | Out-Host
```

Выводит адреса, итог, процессы под защитой и состояние брандмауэра, ничего не блокирует и не пишет конфиг. Код выхода 0, если IP разрешён. Из обычного терминала запуск идёт через UAC, и результат открывается в отдельном окне.

### Сборка

Нужен .NET 10 SDK.

```powershell
dotnet publish windows/Zaslon.csproj -c Release -o out    # out\Zaslon.exe, один файл со встроенным .NET
```

Собирать exe для запуска нужно на Windows: только там в exe вшиваются манифест с правами администратора и иконка. На macOS и Linux `dotnet build windows/Zaslon.csproj` годится для проверки компиляции.

Иконку `windows/AppIcon.ico` рисует тот же `icon.swift` (на Mac):

```sh
xcrun --sdk macosx swiftc -sdk "$(xcrun --show-sdk-path)" icon.swift -o build/make-icon && build/make-icon windows/AppIcon.ico
```

## Сборка из исходников

Нужен Xcode. Зависимостей нет.

```sh
./build.sh                                        # build/Zaslon.app, универсальный бинарник
./dmg.sh                                          # build/Zaslon-<версия>.dmg
build/Zaslon.app/Contents/MacOS/Zaslon --check    # проверка IP без паузы и без записи конфига
open build/Zaslon.app
```

Две запущенные копии (из `build/` и из «Программ») работают независимо друг от друга, и каждая ставит приложения на паузу. Перед запуском одной закрой другую.

Иконку рисует `icon.swift` из векторов, каждый размер отдельно. Готовый `AppIcon.icns` лежит в репозитории. Пересобрать после правки:

```sh
xcrun --sdk macosx swiftc -sdk "$(xcrun --show-sdk-path)" icon.swift -o build/make-icon && build/make-icon AppIcon.icns
```

## Выпуск версии

1. Подними `CFBundleShortVersionString` в `Info.plist`.
2. Добавь раздел `## <версия> — ДД.ММ.ГГГГ` в `CHANGELOG.md`.
3. Создай и отправь тег: `git tag v<версия> && git push origin v<версия>`.

GitHub Actions (`.github/workflows/release.yml`) соберёт DMG и exe для Windows с той же версией и опубликует релиз. Описание релиза берётся из раздела CHANGELOG. Если тег не совпадает с версией в `Info.plist`, сборка остановится.
